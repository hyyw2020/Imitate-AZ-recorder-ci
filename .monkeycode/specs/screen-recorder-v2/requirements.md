# 屏幕录制 V2 需求文档

## EARS 需求规格

### 1. 音频录制

#### 1.1 音频源选择
- **R1.1.1** 当用户选择"静音"作为音频源时，系统应录制纯视频（无音轨），生成仅含视频轨道的 MP4 文件。
- **R1.1.2** 当用户选择"麦克风"作为音频源时，系统应通过 `MediaRecorder.AudioSource.MIC` 采集音频，编码为 AAC-LC（44.1kHz，立体声，128kbps），并作为独立音轨写入 MP4。
- **R1.1.3** 当用户选择"内部音频"作为音频源且设备运行 Android 10+ 时，系统应通过 `AudioPlaybackCapture` API 采集设备内部播放的媒体/游戏音频，编码为 AAC-LC 并写入 MP4。设备低于 Android 10 时应降级为麦克风采集并提示用户。
- **R1.1.4** 当用户选择"内部音频+麦克风"且设备运行 Android 10+ 时，系统应同时采集内部音频和麦克风音频，分别编码为两个独立的 AAC 音轨写入 MP4。设备低于 Android 10 时应降级为仅麦克风采集。

#### 1.2 音频编码参数
- **R1.2.1** 音频编码格式固定为 AAC-LC，采样率 44100Hz，双声道（立体声），比特率 128kbps。
- **R1.2.2** 音频编码器应优先选择硬件加速 AAC 编码器（C2/OMX），不可用时回退到软件编码器。

### 2. 录制控制

#### 2.1 暂停/恢复
- **R2.1.1** 当用户点击悬浮窗"暂停"按钮时，系统应暂停视频帧编码输出（停止从 VirtualDisplay 消费帧），暂停音频采集，时长计时器继续运行但视觉指示器变为闪烁状态。
- **R2.1.2** 当用户点击悬浮窗"恢复"按钮时，系统应恢复视频帧编码和音频采集，继续向 MP4 写入数据，保持同一文件连续录制。

#### 2.2 停止
- **R2.2.1** 当用户点击悬浮窗"停止"按钮或通知栏"停止"按钮时，系统应停止所有采集、刷新编码器缓冲区、完成文件写入，输出有效的 MP4 文件。
- **R2.2.2** 当系统停止 MediaProjection（如用户从快捷设置取消投射）时，系统应自动停止录制并保存文件。

### 3. 高级录制模式

- **R3.1** 当用户选择"高级"录制模式时，编码器应使用 I 帧间隔=1、比特率提升 20%、VBR 码率控制模式、优先级=1。
- **R3.2** 当用户选择"默认"录制模式时，编码器应使用 I 帧间隔=2、标准比特率、CBR 码率控制。

### 4. 架构整合

- **R4.1** `ScreenRecorderService` 应委托录制核心逻辑给 `RecorderEngine`，消除 `ScreenRecorderService` 中的重复编码管道代码。
- **R4.2** `RecorderEngine` 应支持可选的音频编码，通过 `AudioCaptureManager` 管理音频采集。
- **R4.3** `RecorderEngine` 的多轨协调机制（`addTrackAndMaybeStart`）应在音频录制启用时等待所有轨道就绪后再启动 muxer。
- **R4.4** 暂停/恢复控制应从 `FloatingView` → `ScreenRecorderService` → `RecorderEngine` 完整传播。

### 5. 错误处理与反馈

- **R5.1** 任何录制步骤失败时应通过 Toast 和诊断日志同时通知用户。
- **R5.2** 录制成功后，Toast 提示文件保存路径。
- **R5.3** 音频采集失败时（如内部音频权限被拒绝），应降级为静音模式继续录制视频。

## 约束条件

- 兼容 Android 7.0 (API 24) 至 Android 16 (API 35)
- 保留现有的诊断日志、崩溃日志、日志导出/清除功能
- 保留现有的设置界面布局和配置项
- 保留现有的权限流程（覆盖层 → 通知 → 电池 → 屏幕采集）
